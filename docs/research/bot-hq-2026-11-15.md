## 0. TL;DR

- **The video's method is the lesson:** list the one thing each product does best, find a repo, API or MCP for each, then give a strong model one long prompt that names all of them. bot-hq is what Fable 5.2 on high built in about 2½ hours of agent time, on a cloud computer, with 12 of 12 rehearsal checks passing.
- **OrphusBot already has most of this**, often more carefully built: a Grok-style app (D-048), bots asking each other (`ask_bot`, §5.3), per-bot screens with Take control (M2.2), xAI realtime voice (Ideas Room, D-052/D-053), MCP connections with OAuth (#25/#35), Google through `gws` (D-039), a shared wiki and vault memory (D-038/D-054), routines, tickets and the Gallery.
- **Real gaps worth taking:** (1) a voice call to *any* bot that drives its computer, not just the Ideas Room's Orchestrator; (2) a Dots-style "Worked for 2m 10s · 7 steps" chip and a live "what it's doing now" line; (3) each bot's soul and memory shown and editable in the app; (4) X search as a bot tool; (5) screens "dressed" as the bot's own computer (home screen with its name and apps); (6) group chats with @mentions; (7) an email inbox per bot (AgentMail or self-hosted).
- **Don't take the Hermes harness swap.** Hermes's selling point (bring your subscriptions, any model) is what Orphus and the claude-bridge already give us, in Rust with System 1 gating. Read Hermes for ideas (SOUL/MEMORY/USER files, Honcho), not as an engine.
- **Skip:** Orgo (we run our own computers on the box, with E2B as overflow), Composio as the auth layer (our MCP OAuth plus `gws` already cover it, and Composio would put every token with a third party), and iMessage (Kelvin is on Android).

### 1.2 The prompt, summarised

The prompt is dictated on screen (20:46–29:28). A verbatim copy is in the local research folder, not here. In short, it asked to:

1. Keep the grokbot-clone design and its xAI voice modes, and give bots X research.
2. Build the computer to look like Bops / Dots, but with **one Orgo computer and one screen per bot**, up to 4–5 bots. A screenshot of Dots' Thinking chip was attached.
3. Replace the clone's own Grok/OpenAI engine with **Hermes** underneath every bot ("wrap or fork its app, or rebuild from the ground up, whatever you think is best"), keeping subscription sign-in and using Claude.
4. Reuse his existing Hermes agent "Doug" on Orgo as the first bot, **without breaking its iMessage link**, and restyle its computer.
5. Wire Composio for sign-in and connectors, and make it work with Hermes.
6. "Think about all these moving parts." One prompt, with nothing else in it.

### 1.3 What came back and the live tests

- Two agent runs (1h 36m and 54m) with three context compactions (≈180K → ≈30K tokens each). The result was deployed at a public Orgo URL with 12/12 rehearsal checks: create bot, view screen, take control, `x_search`, Composio, voice, delete bot.
- **Sign-in** with Google through Composio, then Gmail and Slack connect cards.
- **Take control** of Doug's screen ("You're driving" / "Hand back to Doug"). It blanks briefly during the handover.
- **Bots talking to bots:** a new bot, "Barbie", asks Doug what he knows about Nick, and the reply comes back into her chat. Doug's thread shows the exchange.
- **iMessage:** a text from the phone is visible to Doug in the web chat within seconds.
- **Voice call that drives the computer:** on a call, Doug opens Chess.com and YouTube in two tabs, switches tab on request, and texts Barbie. Every voice turn and tool step is logged in the chat ("Asked on a voice call").

## 2. How bot-hq is built (from its repo)

- **Shape:** `web/` (React, zustand) + `server/` (Node 22, Hono, SQLite in WAL mode). One SSE stream per user carries row updates, live state and the roster. A WebSocket relays VNC, and the server does the VNC auth, so the computer's password never reaches the browser. In watch mode it drops input on the server.
- **Engines:** each bot is a Hermes gateway reached at `POST /v1/responses`, streaming. The first bot is the Hermes agent already on the computer, whose config the app never rewrites. Every other bot gets its own Hermes home and gateway (ports from 8650), with its own model, sign-in, memory, browser profile (`BH_HOME`) and files.
- **App tools over MCP:** `POST /mcp/<bot>` gives `x_search`, `save_file`, routines, tasks, check-ins, `send_to_bot`, group chats, `ask_user`, `request_app_connection` and the user's Composio tools. Approvals happen *inside the MCP call*: reads run at once, writes post a card (Allow / Always allow / Don't allow), and a new user message or a timeout returns "skipped". It does not cover what a bot does in its browser or shell. This is the same idea as our gate, but narrower.
- **Transcript model:** append-mostly rows (`seq`, a per-bot `updatedSeq` so a streaming reply is one row rewritten, `kind`, JSON body). Kinds are `message`, `tool-call`, `card`, `event` and `notice`. A `generation` counter starts a new conversation.
- **Screens:** one Orgo Linux computer. The first bot uses the main screen and others lease Orgo screens (four per computer). Before a bot's first turn the screen is "dressed": wallpaper, dock, light theme, its own Chrome with a DevTools port, and a home screen (clock, bot name, role, its apps) as Chrome's new-tab page. This stops the agent finding an empty screen and starting a stray browser.
- **Group chats:** a bot row with `kind='room'` and members. A message goes to the @mentioned members, or to all of them, up to 3.
- **Voice:** the server mints short-lived xAI realtime secrets and the browser talks to xAI directly. Real work is handed to the bot's own turn queue, and the result is spoken. This is the same pattern as our Ideas Room, except it works for every bot.
- **Memory:** Hermes's own `memories/MEMORY.md` and `USER.md` per bot. The app lists the entries and lets you delete one.

## 4. Recommendation (the council)

1. **Copy the method, not the stack.** Hand Fable 5.2 a prompt in the video's shape: one line per feature saying *what we like, where it's from, and the repo or doc to read*. Give it §3 of this document as the feature list and DESIGN.md as the ground truth. Ask for a plan and DECISIONS entries before code.
2. **Keep our architecture.** Rust server and node, Orphus engine, System 1 gate, our own computers. bot-hq's approvals stop at the MCP boundary, and ours cover the shell and the browser too. Nothing in the video justifies a harness swap.
3. **Order of work** (cheapest first, most visible first):
   1. Thinking chip + step fold-up + "doing now" line (app and web).
   2. Dressed screens: a home page with the bot's face, name, role and apps, opened before the first turn.
   3. Soul and memory panel per bot: view and edit instructions and the bot's own wiki notes.
   4. `x_search` bridge tool through xAI, gated as a read.
   5. Voice calls with any bot: generalise the Ideas Room (an `ask_<bot>` tool and per-bot voice), log every voice turn in the chat.
   6. Optional: a light group chat, and a per-bot email inbox.
4. **Each item gets its own PR, DECISIONS entry and CHANGELOG line**, following the repo rules.
